# Managed RPC Mode

Managed mode is the RPC mode a host such as Veyra Hands uses to run Fingers inside a sandbox. It speaks the
Fingers RPC v1 contract, which lives in the `veyraco/platform` repository (`contracts/v1/fingers-rpc.md` with
its JSON Schemas and golden transcripts). This page describes what this Fingers version implements.

```bash
fingers --mode rpc --managed
```

`--managed` requires `--mode rpc`. Fingers then builds its session only after the host's `configure` command, so
no other CLI option selects the model, tools or working folder.

## What managed mode adds

| Area | Behaviour |
| --- | --- |
| Handshake | Fingers writes `hello` first (`protocol: veyra.fingers.rpc.v1`, `capabilities`). The first command must be `configure`; `credentials` must arrive before the first `prompt`. |
| Correlation | Every stdout record except a `response` carries `seq`, strictly increasing from 1. Every command should carry a W3C `traceparent`; a command without one starts a new trace and logs a warning. Every model request (turns, compaction, summaries) sends a `traceparent` that is a new child span of the command that started the run (a `steer` or queued prompt joins the running run's trace) and the run's `X-Request-Id` from `configure.request_id`, replacing any value of those headers from `credentials`. |
| Models | `configure.model` names a model of Fingers' catalog (or models.json), except for provider `openai-compatible`: Fingers builds that model itself from `model_id`, and the following `credentials` message's `base_url` points it at the host's endpoint (OpenAI chat completions). No catalog or models.json entry is needed. The contract carries nothing else about the model, so it gets the defaults of a models.json custom model: text input, no reasoning, a 128000-token context window, 16384 output tokens and no price (`cost_source: unknown`). A request before a `base_url` arrived fails instead of going to a default endpoint. |
| System prompt | `configure.system_prompt` (the host's instructions; Hands sends `RunTask.instructions`) is added verbatim to the end of Fingers' own system prompt (identity, tools, rules), for every model request of the session. It never goes into a user message and is never read as a file path, even when the text names an existing file. After `checkpoint_import` the importing process's `configure.system_prompt` applies. The `configured` log line carries its length (`system_prompt_chars`), never the text. |
| Logs | stderr carries JSON log lines in the platform format (`service: "fingers"`, `run_id`, `request_id`, `trace_id`, `span_id`). Set the level with `FINGERS_LOG_LEVEL` and the `env` field with `FINGERS_ENV`. |
| Credentials | The model credential and header values arrive only in `credentials` and `configure` (never argv or the environment) and stay in memory. The secrets (the credential, and the values of credential-named headers that are 8 characters or more: `authorization`, `proxy-authorization`, `cookie`, `x-api-key`, `api-key`, or a name containing `auth`, `token`, `secret`, `key`, `password`, `session`, `signature` or `credential`; the Hands runner's rule) are removed from every stdout record, log line, session file and checkpoint. Removal replaces text inside string values and keys only, so a record keeps its JSON structure; other header values such as `anthropic-version` are not secrets. |
| Policy | Extension, package, skill, prompt template and theme discovery are off; the project is never trusted; cache warming is off; only the built-in MCP extension is loaded. File tools may not leave `workspace.root` or touch `workspace.protected_paths` (symlinks resolved, path spellings expanded as the tools expand them). Shell commands are left to the host sandbox. |
| Approvals | `tools.approval` (`never`, `write_tools`, `always`) and each MCP server's `approval` decide which calls send `approval_request`. The call waits for `approval_response`; `allow_always` adds the request's `allow_always_pattern` to this process's allow list. A denial reaches the agent as `Denied: <reason>`. |
| MCP | `configure.mcp_servers` are Streamable HTTP servers; their tools are declared directly as `mcp__<server>__<tool>`, limited to `allowed_tools` when given. |
| Browser | `tools.builtin` with `browser` adds a headless Chromium tool (`navigate`, `text`, `screenshot`, `click`, `type`, `evaluate`, `close`); `hello` announces `browser` only when Fingers finds a browser (`FINGERS_BROWSER_PATH`, or a standard install location; `PATH` is never searched), and `configure` fails otherwise. The browser starts on the first call with a fresh temporary profile, deleted when the session ends. Every request it makes (pages, subresources, WebSockets) goes through a proxy inside Fingers that applies `configure.network`: `open` (default) or `allow_list` with `hosts` (`name`, `*.domain`, `[ipv6]`, optional `:port`; without a port 80 and 443); link-local and cloud metadata addresses are always refused, also when a listed name resolves to one. The browser resolves no name itself, does not use QUIC or UDP outside the proxy, refuses downloads and dismisses dialogs. The result lists the refused `host:port`s. Only http(s) URLs open; a page that ends on another scheme is left for `about:blank` without returning its content. Under `write_tools` `navigate`, `click`, `type` and `evaluate` ask (kind `network`, `allow_always_pattern` `browser navigate <host>` or `browser <action>`); `text`, `screenshot` and `close` do not. Logs carry the origin, never the path, query, typed text or page content. In a container without user namespaces set `FINGERS_BROWSER_NO_SANDBOX=1` (the Fingers image does; the pod is the sandbox). |
| Usage | A `usage` record follows every model call, with the call's and the process' token counts and list-price cost (`cost_source: unknown` and one `cost_unknown` notice when the model has no price). |
| Files | A `file_changed` record follows every successful `edit` or `write` (shell commands are not tracked). |
| Limits | `max_cost_usd`, `max_output_tokens` and `max_turns` stop the run after the turn in which they are reached; `max_duration_ms` aborts at once. The run then ends with `notice` `limit_reached` and a `result` with `status: stopped`. Limits hold for the whole process: a later `prompt` makes no model call and gets a run of its own that ends the same way (`agent_start`, `notice`, `agent_end`, `agent_settled`, `result` with `turns: 0`). |
| Checkpoints | `checkpoint_export` writes the session (header and every entry, secrets removed, mode 0600, written atomically) to a path inside `configure.checkpoints.dir` and answers with its id, `sha256`, size, leaf `entry_id` and message count (the recorded system prompt included), then emits `checkpoint_created`. `checkpoint_import` reads a file from that directory, checks `sha256`, stores it as a session of this workspace and either resumes it (same `session_id`, identical transcript) or forks it at `entry_id` (default: the leaf) into a new session whose parent is the stored checkpoint. Paths are checked as written and after resolving symlinks (`path_not_allowed`); an import is refused while a run is active (`busy`). |
| Session replacement | `fork`, `clone` and `checkpoint_import` build a new session runtime; the credentials the host sent are applied to it again, so no new `credentials` message is needed. |
| Memory | `configure.memory.mode: relay` turns on the memory relay (announced as `memory_relay`); `off` (default) keeps memory off and the memory tools away. Fingers never calls Brain and holds no Veyra token: each memory operation is a `memory_request` (`id` `memreq_<n>`, `op` `context`, `recall`, `remember` or `events`, Brain's request body without a space or an organization, `timeout_ms`) that the host answers with `memory_response`. At the first prompt of the session Fingers asks for `context` with the task and `max_tokens` = `memory.context_budget_tokens` (default 2000; under 50 asks for none), waits up to 3 seconds, adds the answer to the system prompt as the `memory` section and keeps it in the session (later prompts, a resume and a checkpoint keep it). The model gets `memory_recall` and `memory_remember` (no approval: they reach only the run's own space through the host). When a run ends, Fingers reports its outcome (`events`, one `outcome` event with id `<run_id>:<entry id>:outcome` and `ref` the Hands run) before `agent_end`. An error answer, an answer that is not the contract's or no answer in time lets the run go on without memory; the first one sends `notice` `memory_unavailable`. A `memory_response` for no waiting request is logged and ignored. Logs carry the request id and op, never the body. |
| Result | A `result` record follows every `agent_settled`. |

## Not available yet

These parts of the contract are not announced in `capabilities` and are refused or ignored:
the telemetry relay and sub-agents. Extension UI `notify` calls are not forwarded in managed mode.

## Contract copies

`packages/coding-agent/src/modes/rpc/managed/contract-schemas.ts` and `test/fixtures/fingers-rpc/` are copies of
the platform contract made by `scripts/sync-fingers-rpc-contract.mjs <platform checkout>`. The managed mode tests
check every stdout record against the schemas and replay the golden transcripts.
